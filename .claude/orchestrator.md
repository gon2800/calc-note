# calc-note 전체 점검 오케스트레이터

사용자가 **"calc-note 전체 점검해줘"** (또는 유사 지시)라고 하면 이 절차를 따른다.

## 1. 병렬 실행
아래 4개 서브에이전트를 **동시에(병렬로)** 실행한다. 각 에이전트는 자기 관점만 보고,
겹치는 지적은 하지 않는다.

| 에이전트 | 관점 | 리포트 파일 |
|---|---|---|
| `design-check` | DESIGN.md 색상 토큰 · 탭 견출지 스타일 · Tabler Icons 규칙 | `.claude/reports/<날짜>-design-check.md` |
| `mobile-ux`    | 갤럭시+삼성인터넷 터치 타겟 · 포커스 · 제스처 충돌 · 키보드 겹침 | `.claude/reports/<날짜>-mobile-ux.md` |
| `perf`         | 파일 용량 · 인라인 스크립트 속도 · 리렌더링 · 이미지/폰트 로딩 | `.claude/reports/<날짜>-perf.md` |
| `pwa-check`    | manifest 유효성 · SW network-first · 오프라인 · maskable 아이콘 | `.claude/reports/<날짜>-pwa-check.md` |

각 에이전트에 전달할 지시:
> calc-note(`/home/gon/calc-note`)를 네 정의 파일(`.claude/agents/<이름>.md`)의 기준으로 점검하라.
> `<날짜>`는 오늘 날짜(YYYY-MM-DD). 상세 리포트를 지정 경로에 저장하고,
> 심각도(높음/중간/낮음) 순 최대 5줄 요약만 반환하라.

## 2. 취합
4개 에이전트의 5줄 요약을 모아 정리한다.

- 각 에이전트별로 **가장 중요한 발견 1건**(가장 높은 심각도)만 뽑아 그 에이전트의 발언으로 만든다.
  발견이 2건 이상이면 "~외 N건" 식으로 짧게 덧붙인다.
- 발견이 없는 에이전트는 발언을 "통과" 또는 "이상 없음" 한마디로 끝낸다.
- 종합 판단은 4개 발언 전체를 심각도로 훑어 **가장 높은 심각도 + 지금 손봐야 할 우선순위**를 2~3줄로 결론낸다.
  같은 근본 원인을 여러 관점이 지적했으면 종합에서 한 번만 언급하고 관점을 병기한다.

## 3. 반환 형식 (대화체 / 회의 느낌)

4개 에이전트가 차례로 발언하고 마지막에 오케스트레이터가 종합하는 형태로 반환한다.

```
[design-check] (발견 있으면 1~2줄, 없으면 "통과" / "이상 없음")
[mobile-ux] (동일)
[perf] (동일)
[pwa-check] (동일)

→ 종합: (전체 심각도 판단 + 지금 다뤄야 할 우선순위, 2~3줄 이내)

상세: .claude/reports/<날짜>-{design-check,mobile-ux,perf,pwa-check}.md
```

### 어투 규칙
- 각 발언은 실제로 말하듯 짧고 자연스럽게. 딱딱한 보고서체("~함", "~로 판단됨") 금지.
- 에이전트당 1~2줄. 근거 수치나 파일 위치는 필요할 때 한 조각만 (`sw.js 47KB`, `index.html:528` 정도).
- 발견 없는 에이전트는 "통과" / "이상 없음" 수준으로만. 길게 늘이지 않는다.
- 전체 응답은 텔레그램 4096자 제한을 고려해 간결하게. 종합은 2~3줄을 넘기지 않는다.

### 포맷 예시
```
[design-check] 탭 아이콘 이미 제거됐네요, DESIGN.md 기준 통과.
[perf] sw.js가 47KB로 좀 커졌어요. 캐싱 전략 바꾸면서 늘어난 듯.
[mobile-ux] 입력창 select() 하이라이트 관련 낮음 심각도 이슈 하나요.
[pwa-check] network-first 전환 확인, 이상 없음.

→ 종합: 심각도 낮음 1건(perf 용량 증가). 지금은 넘어가도 되는 수준입니다.

상세: .claude/reports/2026-09-04-{design-check,mobile-ux,perf,pwa-check}.md
```

## 규칙
- 오케스트레이터는 코드를 직접 수정하지 않는다. 점검·보고까지만.
- 어떤 에이전트가 "이상 없음"이면 그 발언도 그대로 남긴다(생략 금지).
- 상세 리포트는 기존대로 각 에이전트가 `.claude/reports/<날짜>-<이름>.md`에 저장한다.
  대화체 요약은 이 파일들을 대체하지 않는다.
- 리포트 파일은 항상 최신 실행으로 덮어쓴다(같은 날 재실행 시).
