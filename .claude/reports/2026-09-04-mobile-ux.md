## 상세

### 1. [높음] 수익성 분석 상세표 가로 스크롤 불가 + 오탭 전환

- 위치: `.pa-table-scroll{overflow-x:auto}` (index.html:304), `.screen{touch-action:pan-y}` (index.html:96), 탭 스와이프 핸들러 (index.html:735-747)
- 현상:
  - `.screen` 에 `touch-action:pan-y` 가 걸려 있어, 그 자손인 `.pa-table-scroll` 에서 가로 팬 제스처가 브라우저 차원에서 억제된다. (조상 체인의 `touch-action` 은 자손의 가로 스크롤을 제한한다.)
  - 추가로 `initTabSwipe` 의 `touchmove` 리스너가 `{passive:false}` 로 `.screen` 에 붙어 있고, `INTENT_THRESHOLD`(10px)만 넘겨 가로 이동으로 판정되면 `e.preventDefault()` 를 호출한다. `.pa-table-scroll` 에서 시작한 스와이프도 이 리스너로 버블링되어 네이티브 가로 스크롤이 취소되고, `touchend` 에서 `resolveSwipe` 가 `switchTab` 을 호출한다.
- 재현 시나리오:
  1. 옥외광고 탭 → 수익성 분석 → '펼쳐보기' 로 `pa-table` (Y1~Y5+소계, 7열, `white-space:nowrap`) 표시.
  2. 표 위에서 좌우로 밀어 뒷열(Y4/Y5/소계)을 보려고 시도.
  3. 표는 움직이지 않고, 대신 나이 탭(왼쪽) 또는 옥외광고가 마지막 탭이라 아무 반응 없음. Y4 이후 열은 사실상 접근 불가.
- 영향: 상세표의 핵심 값(누적FCF·누적DCF·소계)을 세로 모드 한 손 사용으로는 볼 수 없다. '엑셀로 내려받기' 로 우회는 가능하나 화면 확인 경로가 끊긴다.
- 수정 제안:
  - `.pa-table-scroll` 에 `touch-action:pan-x` 를 명시하고, 스와이프 핸들러 `touchstart`/`touchmove` 에서 `e.target.closest('.pa-table-scroll, [data-hscroll]')` 이면 `tracking=false` 로 조기 반환.
  - 또는 상세표를 가로 스크롤 대신 세로 카드형(연도별 블록)으로 재배치.

### 2. [높음] 당겨서 새로고침으로 인한 입력값 유실

- 위치: `html,body{height:100%}` (index.html:29), 스크롤 컨테이너 `.screen{overflow-y:auto}` (index.html:96). 문서 어디에도 `overscroll-behavior` 없음.
- 현상: `.screen` 을 최상단까지 스크롤한 뒤 계속 아래로 당기면 스크롤 체이닝이 `body` 로 전파되어 삼성인터넷 기본 당겨서 새로고침이 동작한다. 페이지가 리로드되면 계산기 수식/히스토리, 나이 입력, 옥외광고·수익성 분석 폼, 추가한 비용 항목이 모두 초기화된다(모두 인메모리 상태, 저장 로직 없음).
- 재현 시나리오: 옥외광고 폼에 값 10여 개 입력 → 화면 위쪽을 보려 스크린 최상단에서 한 번 더 아래로 당김 → 새로고침 → 전부 소실.
- 수정 제안: `.screen{overscroll-behavior-y:contain;}` (가능하면 `body` 에도 `overscroll-behavior:none`). 부수적으로 입력값 `localStorage` 자동 저장 고려.

- 수정 제안: 탭 `min-height:44px`(또는 `padding` 상하 14px), swap 버튼 `width/height:44px` + `padding` 로 아이콘만 20px 유지, select/입력창 `height:44px`, more-btn `padding:12px 0`, 커밋션 입력 `min-width:56px`.

### 4. [중간] 핀치 줌 차단

- 위치: `<meta name="viewport" content="... maximum-scale=1.0, user-scalable=no">` (index.html:5)
- 현상: 사용자 확대(핀치 줌)를 완전히 차단. 본문에는 11~12px 텍스트가 다수 — `.rate-info`(11px), `.result-label`/`.result-sub`(11px), `.oa-footnote`(11px), `.pa-table`(11px), `.detail-row`(13px). 저시력 사용자가 결과값·각주를 확대해 볼 수 없다.
- 삼성인터넷은 "확대/축소 및 글꼴 크기" 설정으로 강제 확대를 켤 수 있으나 기본값에서는 이 메타가 우선한다.
- 커스텀 키패드(계산기)는 `<input>` 이 아니므로 입력 시 자동 확대 이슈는 없다. 즉 `user-scalable=no` 로 얻는 이득이 적고 접근성 손해가 크다.
- 수정 제안: `maximum-scale`/`user-scalable` 제거 또는 `maximum-scale=5`. 레이아웃은 `#app{max-width:430px}` 로 이미 안정적이라 확대 허용해도 깨지지 않음.

### 5. [중간] 하단 입력창·동적 추가 항목의 키보드 겹침

- 위치: `addCostItem` (index.html:1306-1318), `.oa-row-sub.pa-commission-row` 입력(index.html:611), `.screen{padding:0 10px 10px}` (index.html:96)
- 현상:
  - `.screen` 은 `position:absolute; height:100%` 이고 `#app` 은 `min-height:100dvh`. 삼성인터넷은 키보드가 올라와도 레이아웃 뷰포트를 리사이즈하지 않으므로, 화면 하단부 입력창(영업수수료율, 비용 항목 금액, 그 아래 '항목 추가')에 포커스하면 브라우저 자동 스크롤에만 의존한다. 자동 스크롤이 키패드 높이를 정확히 반영하지 못하면 입력 중인 값이 키보드에 가린다.
  - `addCostItem` 은 새 행을 `appendChild` 만 하고 스크롤 이동이 없다. 키보드가 이미 떠 있는 상태에서 '항목 추가'를 누르면 새 행이 접힌 영역/키보드 뒤에 생성되어 보이지 않는다.
  - `safe-area-inset-bottom` 미처리: `.screen` 하단 패딩 10px 뿐. 제스처 내비게이션 바 + 삼성인터넷 하단 툴바(약 48px) 아래로 '엑셀로 내려받기' 버튼·각주가 들어가 탭하기 어렵다.
- 수정 제안:
  - 숫자/텍스트 입력 `focus` 시 `el.scrollIntoView({block:'center'})` (또는 `visualViewport` 기반 보정).
  - `addCostItem` 마지막에 새 행 `scrollIntoView` + 이름 입력창 `focus`.
  - `.screen{padding-bottom:max(10px, env(safe-area-inset-bottom));}` , 필요 시 마지막 카드에 하단 여유 패딩.

### 6. [낮음] 탭 피드백 부재

- 위치: `*{-webkit-tap-highlight-color:transparent}` (index.html:23). `:active` 스타일이 있는 것은 `.btn`, `.quick-card`, `.primary-btn`, `.pa-download-btn` 뿐.
- `.tab-item`, `.history-line`, `.more-btn`, `.rate-swap`, `.pa-add-btn`, `.unit-tab`, `.oa`/`.pa` 입력 라벨 영역은 탭 하이라이트도 없고 `:active` 도 없어, 눌렀을 때 즉각적 시각 반응이 전혀 없다. 반응이 없다고 느껴 사용자가 연타 → 탭 전환 애니메이션 중(`tabSwitching` 가드) 입력 무시와 겹쳐 "먹통" 인상.
- 수정 제안: 해당 요소에 `:active{opacity:.6}` 정도의 최소 피드백 추가, 또는 탭바만이라도 `-webkit-tap-highlight-color` 예외.

### 7. [낮음] 탭 히스토리 미연동

- 위치: `switchTab` (index.html:658-703). 탭 전환 시 `history.pushState` 없음.
- 현상: 사용자는 스와이프/탭으로 5개 화면을 오간 뒤 안드로이드 뒤로가기(제스처 또는 버튼)를 누르면 "이전 탭"을 기대하지만 앱(PWA standalone)이 그대로 종료/이탈한다.
- 부수: 좌측 가장자리 스와이프는 시스템 뒤로가기와도 겹친다(앱 스와이프 임계 `SWIPE_MIN_X:50` 이전에 시스템이 채감). 완전 회피는 불가하나, 탭을 history 엔트리로 만들면 최소한 뒤로가기가 자연스러워진다.
- 수정 제안: `switchTab` 에서 `history.pushState({tab:t}, '')`, `popstate` 에서 해당 탭 복원.

## 범위상 확인했으나 문제 없음

- `100dvh` 만 사용하고 `100vh` 와 혼용하지 않음 (index.html:35) → 주소창 접힘 시 레이아웃 튐 없음.
- 계산기 키패드는 `<input>` 이 아닌 `<button>` → 커스텀 키패드에서 시스템 키보드가 뜨는 문제 없음.
- 숫자 입력칸 모두 `inputmode` 지정: `decimal`(환율·단위·수수료율), `numeric`(옥외광고·나이) → 적절한 키패드 노출. `type="number"` 미사용으로 스피너·로케일 파싱 이슈 없음.
- 나이 입력 `type="tel" + inputmode="numeric" + maxlength` + 자동 포커스 이동 → 삼성인터넷에서 숫자 키패드 정상.
- 포커스 시 전체 선택 로직(`initSelectAllOnFocus`, index.html:949-980)은 삼성인터넷의 커서 재배치를 double-rAF + `touchend` 재선택으로 방어 — 의도된 처리.
- `.calc-history` 내부 세로 스크롤은 스와이프 핸들러가 세로 이동을 `tracking=false` 로 흘려보내 네이티브 스크롤 유지.
- 세로 스와이프(`Math.abs(dx) <= Math.abs(dy)`) 판정으로 탭 전환과 세로 스크롤 충돌은 방지됨. `touchcancel` 폴백도 처리.
- `env(safe-area-inset-top)` 은 헤더에서 `max()` 로 처리 (index.html:45-46). (하단은 미처리 — 항목 5 참조.)
