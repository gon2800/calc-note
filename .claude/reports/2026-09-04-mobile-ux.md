### H-1. 가로 스크롤 표(`.pa-table-scroll`)를 탭 스와이프 핸들러가 가로챔
- **위치**: 스와이프 핸들러 `index.html:735-747`, 대상 요소 `index.html:304`(`.pa-table-scroll{overflow-x:auto}`), 마크업 `index.html:637-638`
- **원인**: `initTabSwipe()`가 모든 `.screen`에 `touchmove`를 `{passive:false}`로 걸고, 수평 이동이 세로보다 크고 10px만 넘으면(`INTENT_THRESHOLD = 10`) `swiping = true` 후 `e.preventDefault()`를 호출한다. 이 리스너는 `.screen`(조상)에 있지만 버블 단계에서 `preventDefault()`가 실행되므로 안쪽 `.pa-table-scroll`의 네이티브 가로 스크롤이 취소되고, 대신 `resolveSwipe()`가 탭 전환을 실행한다.
- **재현 시나리오**:
  1. 옥외광고 탭 → "수익성 분석" → "펼쳐보기 ▾"로 5년 추정표를 펼친다.
  2. 표(Y1~Y5 / 소계 열)를 좌우로 스크롤하려고 손가락을 수평으로 민다.
  3. 표는 움직이지 않고 화면이 이전/다음 탭(나이 또는 옥외광고 내 첫 화면)으로 전환된다.
- **영향**: 5년 추정표의 Y2 이후 열·소계 열을 볼 수 없음. 표 다운로드 전 화면 확인이 불가능. 엑셀 파일이 유일한 열람 수단이 됨.
- **수정 제안**:
  - 스와이프 시작 지점(`touchstart`의 `e.target`)이 `overflow-x:auto`인 조상(`el.closest('.pa-table-scroll, .tab-bar, [data-hscroll]')`) 안이면 해당 터치에 대해 `tracking = false`로 두어 스와이프 추적 자체를 포기한다.
  - 또는 `touchmove`에서 안쪽 스크롤 컨테이너가 아직 스크롤 여유(`scrollLeft`가 0도 max도 아님)가 있으면 `preventDefault()`를 호출하지 않는다.

### H-2. 가상 키보드가 하단 입력칸·버튼을 가림 (스크롤로 못 피함)

  3. 숫자 키패드가 올라오면서 방금 탭한 입력칸 또는 그 아래 "항목 추가" / "엑셀로 내려받기" 버튼이 키패드에 가려지고, 위로 스크롤해도 키패드 위 영역으로 끌어올려지지 않는다.
- **영향**: 값 입력 중 현재 입력칸/결과가 보이지 않음. `addCostItem()`으로 새 항목을 추가하면 새 행이 리스트 맨 아래(키패드 뒤)에 생겨 바로 입력하기 어려움. 환율/단위 탭의 두 번째 입력칸(`toVal`, `toUnitVal`)도 화면이 짧은 기기에서 동일 위험.
- **수정 제안**:
  - 뷰포트 메타에 `interactive-widget=resizes-content` 추가.
  - 높이를 `100dvh` 고정 대신 `#app{min-height:100dvh}` + `.screens`가 실제 가용 높이를 따르도록 하고, `visualViewport` `resize` 이벤트에서 활성 입력칸을 `scrollIntoView({block:'center'})` 하는 보정 코드 추가.

## 중간

### M-1. 스와이프 판별 임계값(10px)이 너무 낮음 — 키패드 오작동 + 시스템 뒤로가기 충돌
- **위치**: `index.html:713`(`INTENT_THRESHOLD = 10`), `index.html:735-747`(touchmove 판정), `index.html:716-723`(`resolveSwipe`, `SWIPE_MIN_X = 50`)
- **원인**:
  - 수평 10px + (`|dx| > |dy|`)만으로 스와이프 모드에 진입하고 `preventDefault()`로 버튼 클릭을 취소한다. 엄지로 키를 누를 때 자연스럽게 생기는 수평 롤(10~20px)이 스와이프로 오인된다.
  - 스와이프 시작 위치에 제한이 없어(`touchstart` 좌표 무관) 화면 좌/우 가장자리에서 시작한 스와이프가 삼성인터넷/안드로이드 제스처 내비게이션의 "뒤로가기"와 동시에 물린다.
- **재현 시나리오**:
  1. 계산기 탭에서 엄지로 `=` 또는 `+`를 누르며 살짝 옆으로 굴린다 → 계산이 안 되고 환율/나이 탭으로 전환.
  2. 화면 왼쪽 가장자리에서 오른쪽으로 스와이프 → 앱은 이전 탭으로 가려 하고 시스템은 뒤로가기(페이지 이탈)를 실행, 둘 중 하나가 비결정적으로 발생.
- **영향**: 계산 중 의도치 않은 탭 전환으로 입력 유실, 첫 탭에서 뒤로가기 시 앱 이탈.
- **수정 제안**:
  - `INTENT_THRESHOLD`를 18~24px로 상향하고, 진입 조건을 `|dx| > |dy| * 1.5` 처럼 각도 기반으로 강화.
  - `touchstart` `clientX`가 화면 폭의 좌우 24px 이내면 스와이프 추적을 포기(시스템 뒤로가기에 양보).
  - 계산기 키(`.btn`) 위에서 시작한 터치는 이동량이 `SWIPE_MIN_X`를 넘기 전엔 `preventDefault()` 보류.

### M-2. `overscroll-behavior` 미설정 — 당겨서 새로고침으로 입력값 소실
- **위치**: `.screen` `index.html:96`, `html,body` `index.html:29`
- **원인**: 스크롤 컨테이너(`.screen`)와 `body` 어디에도 `overscroll-behavior`가 없다. `.screen` 최상단(`scrollTop === 0`)에서 아래로 당기면 스크롤 체이닝으로 삼성인터넷의 당겨서 새로고침이 발동한다. 앱은 입력값을 저장하지 않으므로 새로고침 시 환율·단위·나이·옥외광고에 입력한 모든 값이 초기화된다.
- **재현 시나리오**: 옥외광고 탭에서 값을 여러 개 입력한 뒤, 화면이 최상단인 상태에서 결과를 다시 보려고 위로 살짝 당김 → 페이지 새로고침 → 입력값 전부 사라짐.
- **영향**: 작업 손실. 옥외광고 재원/수익성 분석처럼 입력 항목이 많은 탭에서 타격 큼.
- **수정 제안**: `.screen`에 `overscroll-behavior-y: contain;`(가능하면 `html,body`에도 `overscroll-behavior: none;`) 추가. 필요 시 `beforeunload` 경고는 과하므로 CSS 처리만 권장.

### M-3. `user-scalable=no`, `maximum-scale=1.0` — 확대 차단
- **위치**: `index.html:5`
- **원인**: 뷰포트 메타가 핀치 줌을 막는다. 삼성인터넷은 접근성 설정("확대/축소 강제 사용")으로 무시할 수 있으나 기본값에서는 확대 불가.
- **재현 시나리오**: 저시력 사용자가 옥외광고 5년 추정표(`font-size:11px`, `index.html:305`)나 `.rate-info`/`.oa-footnote`(11px)를 확대해 읽으려 핀치 → 확대되지 않음.
- **영향**: 작은 글씨가 많은 화면(추정표, 각주, 환율 정보줄)에서 가독성 접근성 저하. Android/삼성인터넷은 입력 포커스 시 자동 확대가 없으므로 `user-scalable=no`의 이득은 사실상 없음.
- **수정 제안**: `maximum-scale`/`user-scalable=no` 제거하고 `content="width=device-width, initial-scale=1"`만 유지. 레이아웃이 우려되면 `maximum-scale=5` 정도로 완화.

### M-4. 하단 `safe-area-inset` 미적용 + `.screen` 하단 패딩 10px
- **위치**: `.screen` `index.html:96`(`padding:0 10px 10px`), `#app` `index.html:32-40`, 헤더만 상단 인셋 처리 `index.html:45-46`
- **원인**: 상단은 `env(safe-area-inset-top)`을 쓰지만 하단 `env(safe-area-inset-bottom)` 처리가 전혀 없다. 제스처 내비게이션 기기의 하단 인셋 + 삼성인터넷 하단 툴바(스크롤로 숨었다가 재등장) 높이만큼 마지막 행이 가린다.
- **재현 시나리오**: 옥외광고 탭 맨 아래로 스크롤 → "엑셀로 내려받기" 버튼과 각주가 하단 툴바/제스처 바에 겹쳐 버튼 하단부 탭이 잘 안 먹음.
- **영향**: 최하단 버튼(다운로드, 항목 추가) 조작성 저하.
- **수정 제안**: `.screen` 하단 패딩을 `calc(16px + env(safe-area-inset-bottom))`로, 또는 `.screens`/`#app`에 `padding-bottom: env(safe-area-inset-bottom)`. 최하단 액션 버튼 아래 여유 24px 이상 확보.

### M-5. 인접 탭 `gap:0` — 상단 탭바 오터치
- **위치**: `.tab-bar` `index.html:55-62`, `.tab-item` `index.html:64-77`
- **원인**: 5개 탭이 간격 없이 붙어 있고 각 탭 높이가 ~35px(H-3)라 세로로도 좁다. 견출지 스타일 유지 위해 `gap:0`.
- **재현 시나리오**: 한 손 엄지로 "단위"를 누르려다 "환율" 또는 "나이"가 선택됨.
- **영향**: 탭 전환 오조작. 스와이프 오작동(M-1)과 겹쳐 탐색 신뢰도 저하.
- **수정 제안**: 활성 탭 배경/모서리 처리는 `::before/::after`로 유지하면서 탭 간 클릭 판정에 최소 4~8px 완충. 또는 각 `.tab-item` 세로 패딩을 키워 높이 44px 확보(세로 오터치 완화).

## 낮음

### L-1. `100dvh` 변동에 따른 레이아웃 튐
- **위치**: `#app{min-height:100dvh}` `index.html:35`
- **원인**: `dvh`는 삼성인터넷 주소창이 스크롤로 접히고 펼쳐질 때 값이 변한다. `#app` 높이 → `.screens`(`flex:1`) 높이 → `position:absolute; height:100%`인 `.screen` 높이가 스크롤 도중 재계산되어 미세한 점프가 발생할 수 있다. `100vh`와 혼용은 없어 심각도는 낮음.
- **수정 제안**: 스크롤 컨테이너 높이를 주소창 변동에 덜 민감한 방식(`100svh` 기준 + 최소 높이)으로 두거나, `.screen` 전환 애니메이션 중에는 높이 재계산 영향을 줄이도록 고정 높이 스냅샷 사용.

### L-2. `.history-line` 탭 타겟 과소
- **위치**: `index.html:114-118`, 핸들러 `useHist()` `index.html:913-918`
- **원인**: 계산 히스토리 줄이 높이 ~18px인데 탭하면 해당 결과를 불러온다. 우측 정렬 텍스트라 실제 히트 영역도 좁음.
- **영향**: 히스토리 재사용이 잘 안 눌림(부가 기능이라 낮음).
- **수정 제안**: `.history-line` 세로 패딩을 6~8px로 키우고 줄 전체 폭을 히트 영역으로.

### L-3. select에 네이티브 화살표 없음 (탭 가능 여부 불명확)
- **위치**: `.rate-select` / `.unit-select` `index.html:156-160, 198-203` (`appearance:none`, 커스텀 화살표 미추가)
- **원인**: `-webkit-appearance:none`으로 드롭다운 표시가 제거되고 대체 아이콘이 없어, 통화/단위 칸이 탭하면 열리는 선택 컨트롤임이 시각적으로 드러나지 않음.
- **영향**: 첫 사용 시 통화 변경 방법을 못 찾을 수 있음(경계선상 아이템, 미적 이슈에 가까워 낮음).
- **수정 제안**: 우측에 작은 ▾ 아이콘(배경 이미지 또는 `.rate-row` 내 아이콘 요소) 추가.

## 점검 시 확인된 정상 항목 (참고)
- 계산기 키패드 `.btn`는 `height:64px`로 충분, `:active` 피드백·`navigator.vibrate` 적용.
- 숫자 입력칸에 `inputmode="decimal"` / `inputmode="numeric"` / `type="tel"`가 적절히 지정되어 삼성인터넷 숫자 키패드가 뜸.
- 계산기는 `<input>` 없이 div 표시 + 커스텀 키패드라 시스템 키보드가 뜨지 않음(의도대로 동작).
- 포커스 시 기존 값 전체 선택(`initSelectAllOnFocus`)이 rAF 2프레임 지연 + `touchend` 재선택으로 삼성인터넷 대응 처리됨.
- 스와이프 핸들러가 `touchcancel`에서도 마지막 좌표로 전환을 시도해 버튼 위 스와이프 씹힘을 보완.
- `.screen`에 `touch-action:pan-y` 지정으로 브라우저의 수평 팬은 차단(단, H-1/M-1의 JS 처리 문제는 별개).
- 브리핑에 언급된 `.rate-row` / `.unit-row`의 `overflow-x:auto`는 실제 코드에서 `overflow:hidden`이라 해당 위치의 가로 스크롤 충돌은 없음(가로 스크롤 충돌은 `.pa-table-scroll`에서 발생 — H-1).
- `100vh`/`100dvh` 혼용은 없음(`100dvh`만 사용).
