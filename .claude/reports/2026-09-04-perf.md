## [높음] 1. Tabler Icons 전체 웹폰트를 아이콘 5개에 사용 — 렌더 블로킹 CDN CSS 238KB + 폰트 845KB

### 측정값
- `index.html:12` 의 `<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.19.0/dist/tabler-icons.min.css">` 는 `<head>` 안의 **동기 렌더 블로킹** 스타일시트다. cross-origin(`cdn.jsdelivr.net`)이며 `<link rel="preconnect">` 가 없다.
- CSS 자체: 237,757 B (gzip 39,437 B). 약 5,800개 아이콘 클래스 정의.
- 참조 폰트 woff2: 864,648 B (`content-length` 확인). CSS 로드 후 즉시 요청되며, 폰트가 도착할 때까지 아이콘 자리는 FOIT(빈 네모).
- 실제로 쓰는 아이콘: `ti-backspace-filled`, `ti-arrows-up-down`, `ti-arrow-narrow-right`, `ti-file-spreadsheet`, `ti-plus` — **5종**.

### 병목 근거
- 저사양 안드로이드 첫 로드에서, `<head>` 의 cross-origin CSS 1건이 first paint 를 지연시킨다(연결 수립 + 39KB gzip 파싱). preconnect 가 없어 DNS/TLS 왕복이 크리티컬 패스에 그대로 들어간다.
- 이어서 845KB woff2 를 받아야 5개 글리프가 렌더된다. 캐시가 없는 첫 방문에서 아이콘 폰트만으로 ~845KB 전송 + FOIT.
- 사용률: 전달 바이트의 99.9%가 미사용(5,800개 중 5개).

### 개선안 / 예상 절감
- 5개 아이콘을 인라인 SVG(또는 단일 `<svg><symbol>` 스프라이트)로 교체하고 `index.html:12` 링크를 **삭제**.
  - 인라인 SVG 5개 ≈ 2~4KB(gzip 후 1KB 수준), `index.html` 에 흡수.
  - 전송 절감: CSS 237,757 B + 폰트 864,648 B ≈ **약 1.07MB 제거**, 렌더 블로킹 요청 1건 제거, 아이콘 FOIT 완전 제거, CDN 연결 왕복 제거.
- (차선책) 링크 유지 시: `<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>` 추가 + 폰트 서브셋(5글리프 woff2 ≈ 2~5KB)으로 self-host. 그래도 인라인 SVG 대비 이점 없음.

## [높음] 2. PWA 아이콘 PNG 과대 용량 — 합계 약 937KB, 432KB 파일을 42px 헤더 썸네일로도 사용

### 측정값
- `icons/icon-192.png`: 432,155 B, 실제 해상도 500×500, 8-bit RGBA, non-interlaced.
- `icons/icon-512.png`: 505,172 B, 512×512, 8-bit RGBA.
- `index.html:357` `<img src="/icons/icon-192.png" alt="계산 노트">` — `.header-icon` 이 `width:42px;height:42px` 로 표시(`index.html:50-51`). 42px 썸네일에 432KB 원본 다운로드.
- `index.html:11` `<link rel="apple-touch-icon" href="/icons/icon-192.png">`.
- `sw.js:13-16` `STATIC_ASSETS` 가 두 PNG 를 install 시 `cache.addAll` 로 **무조건 선캐시** → 첫 설치에서 937KB 강제 다운로드.

### 병목 근거
- 앱 아이콘 용도의 단순 그래픽(평면 색/도형)인데 RGBA PNG 무압축 수준으로 저장돼 512px 기준 통상 대비 10~20배 크다(최적화 시 512px ≈ 20~40KB, 192px ≈ 8~15KB).
- 헤더 이미지는 화면상 42×42(HiDPI 고려 ~126px)면 충분한데 500×500 원본을 받아 디코딩까지 한다(저사양 기기에서 메인스레드 디코드 비용).
- SW 선캐시라 오프라인 대비는 되지만, 첫 방문 설치 트래픽에 937KB가 그대로 얹힌다.

### 개선안 / 예상 절감
- 두 PNG 를 `pngquant`/`oxipng` 로 재인코딩하거나 WebP 변환. 예상: 192 → ~12KB, 512 → ~30KB. **약 895KB(≈96%) 절감**.
- `icon-192.png` 은 실제 500×500이므로 정확히 192×192로 리사이즈(파일명-해상도 불일치 정리).
- 헤더 전용 소형 이미지 추가(예: `icon-96.png` ~3KB) 후 `index.html:357` 에서 참조. 또는 헤더 아이콘을 인라인 SVG 로.
- `<img>` 에 `width="42" height="42"` 속성 명시(현재 부모 고정 크기 + `object-fit:cover` 라 CLS 위험은 낮음, 예방 차원).

## [중간] 3. 수익성 분석 상세표를 매 키 입력마다 전체 innerHTML 로 재생성 (접혀 있어도)

### 측정값
- `index.html:1405` `calcPA()` 는 `pa_revenue`, `pa_invest`, `pa_commission_rate` 의 `oninput`(각 `index.html:587,592,611`)과 각 비용항목 행의 `oninput`(`index.html:1313-1314`)에서 호출된다.
- `calcPA()` 는 끝에서 항상 `renderPADetail(paLastData)` 를 호출(`index.html:1461`).
- `renderPADetail` 은 `<table class="pa-table">` 를 문자열 concat 으로 만들어 `#pa_detail_table.innerHTML` 에 대입(`index.html:1362-1396`). 행 ≈ 18개 × 열 7개 + `paRowHTML` 내부 `arr.map`/`reduce` 다수.
- 상세 패널 `#pa_detail_wrap` 은 기본 `.hidden`(`index.html:637`), 사용자가 "펼쳐보기" 를 눌러야 표시(`index.html:1399-1403`).

### 병목 근거
- 패널이 접혀 화면에 안 보이는 상태에서도 키 입력마다 테이블 HTML 문자열 생성 + `innerHTML` 파싱(DOM 100+ 노드 재구축)이 발생한다. 완전한 낭비 작업.
- `oninput` 핸들러에 디바운스/쓰로틀이 없어 빠른 타이핑 시 프레임마다 파싱·레이아웃.
- `calcPA` 는 매 호출에서 `document.querySelectorAll('.pa-cost-row')` 후 행마다 `querySelector` 2회(`index.html:1412-1415`) + `calcIRR` 이분법 최대 100회 반복(`index.html:1325`).

### 개선안 / 예상 절감
- `renderPADetail` 호출을 `if (paDetailShown)` 로 가드하고, `paToggleDetail` 에서 펼칠 때 1회 렌더. → 접힌 상태 입력 시 테이블 빌드/파싱 **0회**(키 입력당 DOM 100+ 노드 재구성 제거).
- `oninput` 계산을 `requestAnimationFrame` 또는 ~120ms 디바운스로 묶기.
- 요약 3값(NPV/IRR/BEP)만 갱신하는 경로와 표 갱신 경로 분리.

## [중간] 4. 5개 스크롤 컨테이너 전부에 non-passive touchmove 리스너

### 측정값
- `index.html:735-747` `initTabSwipe` 가 `document.querySelectorAll('.screen')`(5개) 각각에 `touchmove` 를 `{ passive: false }` 로 등록하고 조건부 `e.preventDefault()` 호출.
- `touchstart`/`touchend`/`touchcancel` 은 `{ passive: true }` 로 등록(양호).

### 병목 근거
- non-passive touchmove 는 브라우저가 스크롤을 시작하기 전에 JS 핸들러 실행을 기다려야 하므로, 저사양 안드로이드에서 세로 스크롤 시작에 지연(스크롤 jank)이 생길 수 있다. 스크롤 영역(`.screen`, `overflow-y:auto`) 자체에 걸려 있어 영향 범위가 넓다.
- 핸들러 본문은 가벼우나(좌표 읽기 몇 번), 매 touchmove 마다 실행된다.

### 개선안 / 예상 절감
- 스와이프 판별을 `touchstart` 에서 축 방향 확정 후, 가로 스와이프로 확정된 경우에만 `touch-action` 을 동적으로 제어하거나, 컨테이너에 `touch-action: pan-y`(이미 `index.html:96` 에 있음)를 신뢰하고 touchmove 를 passive 로 전환.
- 최소한 리스너를 `.screen` 이 아니라 `.screens` 래퍼 1개에 위임(5개 → 1개).

## [낮음] 5. 초기화 시 calcPA 2~3회 실행 · 죽은 CSS 규칙 · 핫패스 getElementById 반복

### 측정값 / 근거
- `paInit()`(`index.html:1464`) → `addCostItem('','')` 호출, 그 안에서 `calcPA()` 1회(`index.html:1317`), 이어 `paInit` 이 다시 `calcPA()` 1회(`index.html:1303`). 로드 시 `calcPA` 가 약 2~3회 실행되며 매번 `calcIRR` 이분법 100회 반복 + `renderPADetail` 테이블 빌드를 입력이 전부 0인 상태에서 수행. (sub-ms 지만 순수 낭비)
- `index.html:22` `.divider{...}` 규칙은 HTML/JS 어디에서도 사용되지 않음(`grep` 결과 0회). 약 60B.
- 핫패스 함수(`convertFX` `convertUnit` `calcPA` `calcOA` `renderCalc`)가 매 키 입력마다 `document.getElementById` 로 동일 노드를 재조회(전체 77회). `calcPA` 한 번에 10개 이상 조회 + 행별 `querySelector` 2회.
- `renderCalc`(`index.html:889`) 는 매 버튼 입력마다 히스토리 `innerHTML` 을 재생성(`index.html:894`). 항목 최대 5개라 영향은 작음.

### 개선안 / 예상 절감
- `addCostItem` 의 말미 `calcPA()` 제거하고 호출측에서 1회만 호출 → 로드 시 계산 1회로 축소.
- `.divider` 규칙 삭제(gzip 후 수십 B, 유지보수성).
- 자주 쓰는 DOM 참조를 모듈 스코프 상수로 캐시(`const elFromCur = ...`). 저사양 기기 키 입력 반응성 미세 개선.
- (참고) 환율 API 는 `loadFX()` 로딩 시 1회만 호출, `setInterval` 폴링/타이머 누수 없음 — 문제 없음.
- (참고) `xlsx.full.min.js` 는 "엑셀 내려받기" 클릭 시 동적 `loadXLSXLib()` 로 지연 로드(`index.html:1469-1478`) — 초기 로드에 영향 없음, 양호.
- (참고) `backup.txt`(33,878 B)는 git 추적되나 `.assetsignore` 로 배포 제외됨(`.deploy/` 에 없음) — 배포 용량 영향 없음.
