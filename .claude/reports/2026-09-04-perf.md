## [높음] Tabler Icons 전체 웹폰트를 렌더 블로킹으로 로드 — 아이콘 5개 쓰려고 약 1.1MB

- 위치: `index.html:12`
  ```html
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@tabler/icons-webfont@3.19.0/dist/tabler-icons.min.css">
  ```
- 실측 비용:
  - CSS 237,757 bytes (약 232KB) — `<head>` 안 동기 `<link>`라 **첫 렌더를 차단**한다.
  - 딸려오는 `tabler-icons.woff2` 864,648 bytes (약 844KB) — 5,800여 개 글리프 전체.
  - 합계 약 1.07MB. gzip 후에도 CSS는 30KB대, woff2는 이미 압축 포맷이라 거의 그대로.
- 실제 사용 아이콘: **5종뿐**
  - `ti-arrow-narrow-right`, `ti-arrows-up-down`, `ti-backspace-filled`, `ti-file-spreadsheet`, `ti-plus`
  - JS 안에서 아이콘 클래스를 동적 생성하는 곳 없음 (템플릿 문자열에 `ti-${...}` 패턴 없음) → 5종이 전부다.
- 저사양 안드로이드 영향:
  - 폰트 로드 전까지 아이콘 자리가 비는 FOIT. 폰트가 844KB라 3G/혼잡 Wi‑Fi에서 수 초.
  - CSS 232KB 파싱까지 본문 렌더가 밀린다.
- 개선안 (효과 큰 순):
  1. 5개 아이콘을 **인라인 SVG**로 교체하고 `<link>` 삭제. 인라인 SVG 5개 = 약 2~4KB. 절감 약 1.06MB, 렌더 블로킹 리소스 1개 완전 제거.
  2. 인라인 SVG가 부담이면 `tabler-icons` 저장소에서 해당 5개 SVG만 뽑아 CSS `mask-image` data URI 또는 단일 심볼 스프라이트로. 마찬가지로 수 KB.
  3. 최소 조치(비권장): 최소한 `media`/`onload` 패턴으로 비동기화하고 `<link rel="preconnect" href="https://cdn.jsdelivr.net">` 추가 — 용량은 그대로라 근본 해결 아님.
- 예상 절감: 초기 임계 경로 약 -1.06MB, 렌더 블로킹 요청 -1, FOIT 제거.

## [높음] PWA 아이콘 PNG 과대 — 937KB, 최적화 시 약 -890KB

- 위치:
  - `index.html:11` — `<link rel="apple-touch-icon" href="/icons/icon-192.png">` (iOS에서 즉시 다운로드)
  - `manifest.webmanifest` 아이콘 참조 (설치 시/스플래시)
- 실측:
  - `icon-192.png` 432,155 bytes, 실제 픽셀은 500×500 (이름과 불일치, 192로 표기됐지만 500px).
  - `icon-512.png` 505,172 bytes, 512×512.
  - 둘 다 8-bit RGBA non-interlaced. 단색·플랫 도형 앱 아이콘이 이 용량이면 압축이 거의 안 된 상태.
- 기준선: 512×512 플랫 아이콘은 보통 15~40KB(팔레트 PNG-8 또는 무손실 재압축), 192는 5~12KB.
- 개선안:
  1. `oxipng -o max` 또는 `pngquant --quality 70-90` 로 무손실/근접무손실 재압축.
  2. 실제로 필요한 크기(192, 512)로 리샘플. `icon-192.png`를 192×192로 줄이면 그것만으로도 대폭 감소.
  3. 여력 되면 `icon-512.webp` 추가 제공(매니페스트는 여러 포맷 허용). apple-touch-icon은 PNG 유지.
- 예상 절감: 두 파일 합계 937KB → 약 40~50KB, **약 -890KB**. (SW `precache` 목록에도 들어가면 첫 설치 트래픽·캐시 용량 동일 절감.)
- 참고: 이 항목은 "manifest 유효성"이 아니라 파일 용량/로딩 관점에서만 지적.

## [중간] CDN 리소스에 preconnect/preload 없음 — 연결 수립 지연

- 위치: `index.html:9–12` 헤드 영역 (리소스 힌트 전무)
- 현황:
  - `cdn.jsdelivr.net` (Tabler CSS, 렌더 블로킹) 에 대한 `preconnect` 없음 → DNS+TLS 왕복이 CSS 요청 직전에 직렬로 발생. 저지연 아닌 회선에서 100~300ms 손해.
  - `open.er-api.com` (환율 fetch, `index.html:1014`) 도 힌트 없음. 초기 실행 경로에서 `loadFX()` 즉시 호출(`index.html:1090`)되므로 `preconnect` 이득.
  - `cdn.sheetjs.com` (`index.html:1473`) 은 사용자가 엑셀 내보내기 누를 때만이라 우선순위 낮음.
- 개선안:
  - Tabler를 인라인 SVG로 없애면 jsdelivr preconnect 불필요 (상위 항목으로 자연 해결).
  - Tabler를 남긴다면 `<link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>`.
  - `<link rel="preconnect" href="https://open.er-api.com">` 추가 권장.
- 예상 절감: 초기 화면 아이콘/환율 표시까지 약 100~300ms.

## [낮음] 인라인 JS/CSS 미압축(비-minify) — gzip 후에도 약 5~8KB 여지

- 위치: `<style>` `index.html:14`, `<script>` `index.html:649`
- 실측: JS 39,249 bytes(gzip 11,625), CSS 14,385 bytes(gzip 3,464). 원본에 들여쓰기·주석·공백 그대로.
- 빌드 단계 없음(터미널에서 `terser`/`esbuild` 흔적 없음). 배포는 원본을 그대로 올림.
- 개선안: 배포 스크립트(`.deploy/`)에 minify 한 단계 추가. HTML 총 68KB→약 55KB, gzip 17.3KB→약 13~14KB.
- 우선순위 낮음: 이미 gzip 17KB로 임계 경로에서 큰 병목 아님. 위 두 [높음] 대비 효과 미미.

## 점검했으나 문제 없음 (근거)

- **타이머 누수 없음**: `setInterval` 0건. `setTimeout`은 탭 전환 정리(`index.html:702`)와 롱프레스(`index.html:930`) 2곳뿐, 둘 다 1회성.
- **환율 API 폴링 없음**: `loadFX()`는 로드 시 1회(`index.html:1090`)만 호출. 재호출은 swap/입력 시 로컬 계산(`convertFX`)뿐, 네트워크 재요청 아님. `fetch`는 비동기라 렌더 차단 안 함.
- **레이아웃 스래싱 없음**: `offsetWidth` 읽기는 탭 전환 트랜지션 강제 리플로우 1곳(`index.html:683`)뿐, 루프 안 읽기/쓰기 인터리브 없음. `getBoundingClientRect`/`scrollHeight` 사용 0건.
- **트랜지션은 합성 속성**: 화면 전환/버튼 눌림 모두 `transform: translateX/scale`(`index.html:140,142,686–688`). `width`/`top`/`margin` 등 레이아웃 속성 트랜지션 0건.
- **패시브 리스너 적용**: `touchmove`/`touchstart` 리스너에 `{ passive: true }` 지정(`index.html:733,756,766,937`). 스크롤 잠금이 필요한 곳만 의도적으로 `{ passive: false }`(`index.html:747`).
- **리렌더 범위 작음**: `innerHTML` 재생성 대상이 전부 소규모 — 히스토리 최대 5줄(`index.html:849`), 환율 퀵카드 8개(로드 시 1회, `index.html:1067`), 단위 드롭다운(단위 종류 변경 시만, `index.html:1145`). 키패드 21버튼은 정적 HTML, 입력마다 재생성 안 함. `DocumentFragment` 필요할 만큼 큰 반복 `appendChild` 없음(유일한 `appendChild`는 옥외광고 비용행 1개씩 추가, `index.html:1316`).
- **무거운 초기화 없음**: 파싱 직후 실행되는 건 `renderCalc()`(빈 상태), `loadFX()`(비동기), 이벤트 바인딩뿐. 큰 루프/정규식 선계산 없음.
- **엑셀 라이브러리 지연 로드**: `xlsx.full.min.js`는 내보내기 클릭 시 동적 `<script>` 주입(`index.html:1472–1476`). 초기 로드에 포함 안 됨 — 바람직.
- **backup.txt 배포 제외**: `.assetsignore`에 `backup.txt`, `CLAUDE.md`, `.claude` 등 명시. `.deploy/`에도 `index.html`/`sw.js`/`manifest`/`icons`만 존재. 죽은 33KB 파일이 배포에 안 들어감.

## 참고 (성능 외, 조치 대상 아님)

- `.deploy/index.html`이 67,200 bytes로 현재 루트 `index.html`(68,320)보다 오래됨 — 배포 스냅샷이 최신이 아닐 수 있음. 성능 항목은 아니고 배포 파이프라인 위생 문제라 여기서는 참고만.
